# Release note

Фрагмент не публикуется в сторы. Ниже факты для ревьюера и граница между JS/OTA и новым бинарником.

## Разрешения

- iOS: файл выбирают через системный document picker, отдельной usage string для файлов не нужно. ATS разрешает только `NSAllowsLocalNetworking`, чтобы ходить к локальному mock по HTTP.
- Android: файл выбирают через системный picker (SAF), приложение получает доступ только к выбранному файлу. Фрагменту нужно только `INTERNET`. В `app/app.json` в `android.blockedPermissions` перечислены `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`, `VIBRATE`. Их добавляют библиотеки Expo и React Native. Запрет попадёт в манифест при следующей нативной сборке. В текущей собранной сборке эмулятора эти разрешения ещё есть в манифесте.
- `android:allowBackup="false"`.
- HTTP без шифрования. В отладочной сборке Android манифест `debug` разрешает HTTP ко всем адресам (`usesCleartextTraffic="true"`). В release-манифесте этого флага нет, и Android по умолчанию HTTP запрещает. В production нужен HTTPS, а на iOS нужно убрать `NSAllowsLocalNetworking`.

## Где лежат копии файла

- Оригинал остаётся там, где его выбрал пользователь (Files, Downloads). Приложение его не трогает.
- Копия picker. На Android picker сам копирует `content://` в `cache/DocumentPicker/`. На iOS система кладёт копию в `tmp/<bundle>-Inbox/`. Приложение удаляет эту копию сразу после проверки файла, в том числе при отказе. Если приложение упало раньше, копия удаляется при следующем запуске. Файл больше 10 MiB, о размере которого picker сообщил заранее, отклоняется до нашей копии, но на Android копию picker к этому моменту уже сделал. Её тоже удаляем.
- Приватная копия приложения: `statement-staging/<uuid>.bin` в cache (`Library/Caches` на iOS, cache приложения на Android). В бэкап не попадает. Удаляется после того, как сервер подтвердил job, при отмене, при отказе, при уходе с загрузки. Оставшиеся после падения копии удаляются при запуске.
- Файл операции `Documents/import-operation.json`. В нём фаза, ключ идемпотентности, ключ удаления, код последней ошибки, `jobId`, статус и ревизия job. Пока загрузка не подтверждена, там же путь к приватной копии, её размер и формат. Имени файла, сумм и названий получателей там нет: после перезапуска отчёт заново читается с сервера по `jobId`. Файл лежит в `Documents`, а не в cache, потому что при очистке cache потерялся бы ключ и повтор создал бы второй импорт. На iOS `Documents` попадает в бэкап, поэтому данных выписки в этом файле нет.
- Mock хранит SHA-256 и метаданные в `kit/.mock-state.json`. Байты выписки он не сохраняет.

Как очистить: удалить приложение. Для mock: `POST /__test/reset` или удалить `kit/.mock-state.json`.

## Что остановит rollout

В production:

- растёт доля повторных запросов создания импорта с одним ключом идемпотентности, или на один выбор файла появляется больше одного job;
- растёт доля загрузок, которые остались неподтверждёнными (экран «Upload not confirmed»);
- растёт доля неудачных или неподтверждённых удалений;
- экран «Deleted» при статусе не `deleted`;
- в логах или краш-репортах есть имя файла, байты или описания операций.

На mock это проверяется счётчиками:

- `GET /__test/state` после одного выбора файла показывает `newJobs > 1`;
- `createRequests` вырос после выбора `spoofed.pdf` или файла больше 10 MiB.

## Новый нативный бинарник, а не JS/OTA

- Смена нативного модуля файлов, picker или загрузки (`expo-file-system`, `expo-document-picker`, `expo-dev-client`).
- URL-схемы, ATS, флаг бэкапа, NDK, разрешения. Сюда относится и `blockedPermissions` из этой версии.
- Смена версии Expo SDK или React Native.

Логика состояний, тексты и диагностика mock меняются через OTA, пока не меняются нативные вызовы: загрузка `uploadAsync` с `BINARY_CONTENT`, копирование `copyAsync`, чтение первых байт через `readAsStringAsync` с `position` и `length`.
